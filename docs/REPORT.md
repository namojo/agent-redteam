# 에이전트 모의 해킹 (Agent Red-Team) — 프로젝트 보고서

> 배포 전 AI 에이전트를 표준 OWASP 프로브로 공격해 취약점을 찾고, 방어 규칙을 적용한 뒤 같은 공격으로 재시험하는 **배포 전 레드팀 하네스**. 삼성SDS 사내 해커톤 주제 후보 **04 에이전트 모의 해킹**을 실제 동작하는 웹 애플리케이션 + CLI 도구로 구현했다.

## 1. 배경 — 왜 이 주제인가

해커톤 주제 후보 10개(`1d344868-topics.md`) 중 **04 에이전트 모의 해킹**을 골랐다. 선정 근거:

- **문제 크기**: 회사가 발표한 「2026년 5대 사이버 보안 위협」의 1순위가 **AI 기반 보안 위협**이며, 그 안에 *AI 에이전트의 과도한 위임·권한 남용*이 포함된다.
- **외부 근거**: OWASP LLM Top 10 2025의 1위가 프롬프트 주입. Gartner 조사(2025-09)에서 보안 책임자 302명 중 32%가 AI 앱 프롬프트 공격을 경험. OWASP가 2025-12 낸 에이전트 앱 Top 10 부록에는 2025년 2~10월 실제 에이전트 사고 22건이 수록.
- **차별성**: 사내에 겹치는 제품이 없다. FabriX Governance가 *운영 중 통제*라면, 이 주제는 *배포 전 공격 시험*으로 앞단에 붙는다.
- **데모 장면**: 공격이 뚫리는 장면과 막히는 장면이 한 화면에 들어온다 — 발표 3분에 "전과 후"가 보인다.

## 2. 무엇을 만들었나

두 가지 산출물.

1. **웹 애플리케이션** (`namojo.github.io/agent-redteam`) — 설치 없이 브라우저에서 바로 쓰는 레드팀 콘솔. **데모 모드**(가짜 데이터만 든 격리 챗봇, 무설정)와 **실제 연결 모드**(사용자 소유/인가 엔드포인트에 실제 HTTP 프로브 전송)를 제공.
2. **CLI 도구** (`agent-redteam`, 이 저장소) — 같은 엔진을 터미널·CI에서 돌리는 제로-디펜던시 Node 애플리케이션. 취약 건수가 임계값을 넘으면 **종료코드 1**로 배포를 막는 게이트.

핵심은 "오용 가능한 공격 무기"가 아니라 **garak·promptfoo·DeepTeam 같은 정식 레드팀 도구**와 같은 방식 — 인가된 대상에 표준 프로브를 던지고, 응답을 탐지 규칙으로 판정하고, 리포트를 낸다.

## 3. 동작 원리

```
프로브 배터리 ──▶ (변형: Base64/ROT13/Leet/분할) ──▶ 대상 엔드포인트
      │                                                      │
      │                                                   응답 텍스트
      ▼                                                      ▼
  멀티턴 크레센도(대화 히스토리 유지) ─────────────▶ 판정
                                                 (sentinel·카나리·국내PII·거절·LLM판정)
                                                      │
                                     취약/차단/미결 집계 ──▶ 배포 게이트(PASS/FAIL)
                                                      │
                                     방어(가드 프롬프트) ON으로 재시험 ──▶ 차단률
```

- **프로브**: LLM01 프롬프트 주입 · LLM02 민감정보 노출 · LLM06 과도한 권한 각 3종(총 9종).
- **판정**: ① 공격이 유도한 sentinel 문자열이 응답에 있으면 취약 ② 카나리(심어둔 비밀값) 유출 ③ 국내 PII 정규식 매치 ④ 거절 표현 → 차단 ⑤ 그 외 LLM 판정(켜면) → 미결 최소화.
- **폐루프**: 방어 ON은 하드닝 가드 시스템 프롬프트를 주입해 같은 배터리를 재실행 → 차단률을 숫자로 증명.

## 4. 핵심 기능 (화면)

### 4.1 데모 — 공격이 뚫린다
프롬프트 주입 한 줄에 데모 HR 챗봇이 가짜 직원 명부를 내준다. "유출 발생" 판정.

![데모 공격 유출](images/02-demo-leak.png)

### 4.2 방어 적용 → 차단
방어 규칙 3종(입력 필터·도구 권한 축소·응답 검사)을 켜면 같은 공격이 차단된다.

![데모 방어 차단](images/03-demo-defense.png)

### 4.3 배포 게이트 (전/후 집계)
일괄 자동 공격으로 취약 건수를 집계하고 PASS/FAIL로 판정한다.

![데모 게이트](images/04-demo-gate.png)

### 4.4 실제 연결 설정
Anthropic·OpenAI·커스텀 프리셋으로 자기 에이전트 엔드포인트를 지정한다. 키는 저장하지 않고, 권한 체크박스를 켜야 실행된다.

![실제 연결 설정](images/05-live-config.png)

### 4.5 실측 리포트 + 게이트 FAIL
실제 엔드포인트에 프로브(+Base64 변형)를 쏘고, 케이스별 판정 표와 게이트 결과를 낸다. `.md` 다운로드 가능.

![실측 리포트](images/06-live-report.png)

### 4.6 멀티턴 크레센도 공격
benign 질문으로 신뢰를 쌓은 뒤 대화를 유지한 채 3턴에 걸쳐 수위를 올린다. 최종 턴 응답을 판정.

![멀티턴](images/07-multiturn.png)

### 4.7 CLI (배포 게이트)
터미널·CI에서 같은 엔진 실행. 취약 > 임계면 종료코드 1로 배포 차단.

![CLI](images/10-cli.png)

## 5. 범용 오픈소스 대비 차별화

![차별화 비교표](images/08-differentiation.png)

| 항목 | 범용 OSS (garak·promptfoo·DeepTeam) | 이 도구 |
|---|---|---|
| 인코딩 공격 변형 | ✓ | ✓ Base64·ROT13·Leet·분할 |
| LLM-as-judge 평가 | ✓ | ✓ 대상 모델 재사용 자체 판정 |
| 멀티턴 크레센도 | ✓ | ✓ 대화 히스토리 유지 3턴 점증 |
| **한국어·국내 PII** | 영어 중심/제한적 | ✓ 주민번호·연락처·카드·비밀토큰 정규식 + 한국어 공격셋 |
| **에이전트 네이티브** | LLM 응답 중심 | ✓ 도구-호출·과도한 위임(LLM06) 프로브 |
| **배포 게이트** | 평가 리포트 위주 | ✓ 취약 0 기준 PASS/FAIL·종료코드 |
| **폐루프 수정** | 탐지 중심 | ✓ 가드 자동 주입 → 재시험 차단률 |
| **사내 연계** | — | FabriX 공급 전 점검 → 거버넌스 |

범용 OSS를 대체하는 게 아니라, **국내 SI·에이전트 공급 맥락의 '배포 전 게이트'**로 포지셔닝한다.

## 6. 규제 매핑

발견을 보안팀뿐 아니라 법무·감사팀의 언어로 옮긴다.

![규제 매핑](images/09-regulation.png)

| OWASP | 공격 유형 | 관련 국내 규제 | 점검 포인트 |
|---|---|---|---|
| LLM01 | 프롬프트 주입 | 개인정보보호법 §29 · 전자금융감독규정 §13 | 접근통제 우회 가능성 |
| LLM02 | 민감정보 노출 | 개인정보보호법 §23·§24 · 신용정보법 §19 | 주민번호·금융정보 응답 유출 |
| LLM06 | 과도한 권한 | 개인정보보호법 §29 · 전자금융감독규정 §13 · ISMS-P 2.6 | 최소권한·타인정보 접근 차단 |

> 조문 번호는 참고용이며 실제 적용은 법무·컴플라이언스 검토가 필요하다.

## 7. 검증

- **웹**: Playwright로 데스크톱/모바일(390px)·라이트/다크 렌더, 데모 전·후, 실제 연결(모의 엔드포인트) 단일/일괄, 권한 게이트, Base64 배터리 확장(9→18), LLM 판정(미결 0), 멀티턴(대화 유지·sentinel 판정), 거절 엔드포인트→취약 0, 가로 넘침 없음을 전수 확인.
- **CLI**: 모의 에이전트(`examples/mock-agent.mjs`) 대상 엔드투엔드 — 취약 엔드포인트 21케이스 전원 취약·게이트 FAIL·종료코드 1, 방어 엔드포인트 전원 차단·게이트 PASS, 권한 미확인 시 종료코드 2. `npm test`로 재현.

## 8. 배포

- 웹: GitHub Pages 자동 배포(`namojo.github.io/agent-redteam`).
- CLI: 이 저장소. `npx agent-redteam` 또는 clone 후 `node src/cli.mjs`.

## 9. 한계와 로드맵

- **LLM 자체 판정 편향**: 대상 모델이 자기 응답을 판정하면 편향이 있을 수 있다 → 별도 judge 엔드포인트 지정을 로드맵으로.
- **CORS**: 브라우저 직접 호출을 막는 엔드포인트는 웹 모드에서 실패 — CLI를 쓰거나 프록시 필요.
- **로드맵**: LLM 기반 공격 자동 진화(적응형 jailbreak), RAG/벡터 경로(LLM08) 프로브, 규제 리포트 서식 확장, GitHub Action 패키징.

## 10. 안전·윤리

- 모의 해킹은 **반드시 인가된 대상**에만. 웹은 권한 체크박스, CLI는 `--yes`/`authorized` 없이는 실행되지 않는다.
- 데모는 격리된 가짜 데이터만 사용. 화면의 공격 예시는 OWASP가 공개한 교육용 유형을 defang한 것이며, 재사용 가능한 공격 페이로드 생성기가 아니다.
- 탐지에 쓰는 sentinel/카나리는 무해한 확인 문자열이다.
